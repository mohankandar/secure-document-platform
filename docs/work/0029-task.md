## 1. Waiting for you (Processor and Supervisor, capability EXPORT_RESEND)
- A navigation item **"Waiting for you"** next to Review, with a count badge. Hidden when there is nothing waiting and in `inline` mode.
- Intro line: "A destination refused these cases. Once the cause is fixed with the destination's team, send them again. Open a case to send just that one."
- **One group per destination:** name, kind ("full case" / "split by barcode"), count, the most frequent reason as "Title · code", and **one "Resend all N" button** in the group's header. **No checkboxes and no buttons on the rows.**
- Rows: case (and document for split), "Title · code", waiting since; **the whole row opens the case** (a real link).
- Footnote: "Each case is sent once more. If the destination refuses it again, it goes to IT with code LV-DLV-015. Cases waiting for a destination that is down are not listed here: they go out on their own when it is back."

## 2. Resend all: confirmation
- Title "Resend N cases to <destination>?"; body: "They go back in the export queue and are sent one by one, in the order they were refused. You can leave this page; it carries on."; a box with the count per reason ("2 refused for the sensitivity level · LV-DLV-003"); the line "Has the destination's team fixed the cause? If not, they will be refused again. Each case is sent once more; a case refused again goes to IT."; buttons **Not now** and **Resend N cases**.
- After: a toast "N cases queued for <destination>. They'll show as "Exporting · ready" until sent."

## 3. The "Exporting" status (owner's name)
- In the Cases list and the case panel, a case with an open export job shows **Exporting · ready**, **Exporting · destination paused**, **Exporting · waiting for you** or **Exporting · needs IT** (from `exportState`), instead of its review status. EXPORTED shows "Exported". NONE: the status as today.
- Case panel stage strip ends with an **Exporting** step.
- Case panel, when waiting for you: a highlighted box "EXPORTING · WAITING FOR YOU", "<destination> refused this case", "Title · code", "Refused today at <time>. Once the destination's team has fixed it, send it again. It gets one more attempt.", and **one "Resend this case" button** (EXPORT_RESEND only). The destination's own code goes under Technical details.

## 4. Support (IT Admin)
- **Needs IT:** one card per group (destination + code): "<count> cases failing to <destination> since <time>", "Title · code", a line on what was already tried (for the retry schedule: "The destination answers its health check, so it's these cases. Each was retried over 24 hours and rebuilt once."), the case ids, and **"Retry all N"** (retry-group). A sign-in failure (LV-DLV-005): "<destination> refused LexaVault's sign-in", "Exports to it are on hold: N waiting, nothing lost. Fix the credential in Admin › Integrations, then set it back to working.", **"Set back to working"**.
- **Destinations:** each with state (Working · Paused since <time> with "Health check failing · next check <time>" · Needs IT with its code), the number waiting, and **"Check now"** for a paused one (runs the probe now; add the endpoint if missing).
- **"LexaVault can't reach its destinations"** alert at the top when raised, with the line: "The problem is likely LexaVault's own network, not the destinations."
- Support's needs-attention badge counts the groups.
