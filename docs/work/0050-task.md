## Build
1. **Clean output, always on:** the redacted PDF is written as a **new file** (no incremental history), and carries none of: document metadata other than a neutral producer and the dates; JavaScript, open actions and other actions; embedded files and attachments; annotations of any kind (comments, links, stamps; say if any must stay, e.g. internal page links, and why it's safe); form fields (flattened to their visible appearance, then removed); hidden optional-content layers (visible layers flattened in, hidden ones dropped). Untouched pages keep their visible content and text layer.
2. **Hidden text:** text drawn invisible (rendering mode 3), outside the page's visible area, or white-on-white is **not removed by default** (it is often the OCR layer of a scan), but it is part of the text that detection reads, so anything sensitive in it is found and redacted like visible text. Add a test proving an SSN in invisible text is found and redacted.
3. **Whole-file final check:** extend 0044's check from page text to **the whole output file**: every decompressed content stream, the remaining metadata, and the names of every object. If a redacted value (4 characters or more, as in 0044) appears anywhere, the document fails closed with `LV-RED-005` (or a new code if the cause should be told apart; say which). Compared in memory, nothing stored.
4. **Signed PDFs:** a digitally signed input can't keep a valid signature after redaction. Record "signature removed by redaction" in the case's audit (no signer names), and show a plain line on the case panel; the output is not signed.

## Prove it
- Test PDFs with each kind of hidden content (made with fake values): each is gone from the output; a value planted in metadata, an attachment, a form field or a hidden layer of an input page is either removed or makes the final check fail closed.
- The 0044 and 0047 tests still pass; searchable pages still work.
- Full backend build with PostgreSQL tests on, `npm run test:standalone`, the no-redacted-value check, the compliance report check, the export end-to-end, the product-name guard.
- Output size and time per document on the benchmark's 60-page package, before and after.
