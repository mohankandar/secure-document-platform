## Part B: the report

**B1. Endpoint.** `POST /api/v1/compliance-reports` returns `application/pdf`, with a safe file name such as `compliance-report-<entity-slug>-<from>-<to>.pdf`.
- Body:
  - `period`: `LAST_MONTH`, `LAST_QUARTER`, `LAST_YEAR` or `CUSTOM`;
  - `from` and `to`: dates, for `CUSTOM` only;
  - `timeZone`: an IANA name, validated, default UTC;
  - `includeFullAuditTrail`: boolean.
- The entity is the request's tenant, the one the person is signed in to. Never take an entity from the body.
- `includeFullAuditTrail=false` needs `COMPLIANCE_REPORT_SUMMARY`; `true` needs `COMPLIANCE_REPORT_FULL`. Refuse anything else with 403, and audit the refusal as the other endpoints do.
- Period rules:
  - "last month", "last quarter" and "last year" are the last complete calendar month, quarter or year in that time zone;
  - `CUSTOM` must end before today and be 1 day to 366 days long;
  - `from` is inclusive and `to` inclusive (to the end of that day).

**B2. Where the numbers come from.** All of them are per entity and for the period.
- **Policy at the end of the period:** the latest `SENSITIVE_DATA_POLICY_CHANGED` record at or before the period end. If there is none, use the current policy and say "(unchanged since before this period)".
- **Changes during the period:** from those records' new and `previous=` keys (0016). Show one line per changed value, in plain words, matching the canvas wording. Use the type names from the vocabulary (`words.ts` names, ported to the server once, for example "Social Security number"). Use the presets when they change ("Balanced → Light").
- **Keeping and deleting:**
  - settings at the end of the period, from `LIFECYCLE_POLICY_CHANGED` the same way;
  - "Originals due for deletion" = cases whose original purge was due in the period;
  - "Deleted on time" = those purged no later than 24 hours after due, from the `ORIGINAL_ARTIFACT_PURGED` successes;
  - "Late or failed" = the rest, including `PACKAGE_PURGED` failures;
  - the count of cases still within their keep time at the period end, for the sentence under the tiles.
  - If the lifecycle data can't give "due", stop and ask.
- **Cases and review:** use the same query and definitions as the Reports page (reporting package facts), so the numbers match Reports for the same period.
  - Rows: Received; Delivered (label "Delivered after supervisor approval" only when approval was required for the whole period, else "Delivered"); Rejected by a supervisor; Still open at the period end.
  - Then "Of the delivered cases": No review needed, Checked by a reviewer, Finished by hand after a processing stop.
  - Shares are rounded to whole %.
- **Audit activity:** counts per row, using the canvas rows: policy changes; keeping and deleting changes; findings decided; cases approved; cases rejected; originals deleted; report exports (CSV); compliance reports created; access refused. List which `AuditAction`s each row counts in the report.

**B3. The PDF** (PDFBox, US Letter).
- Layout and wording match the canvas. Use the canvas's sample content only as a guide to structure, never in the output.
- **Fonts:** IBM Plex Sans and Mono, embedded. Look for TTF files the app already bundles. If there are only woff2, add the TTF files and the OFL licence under the backend's resources, then say so in the report. Never load fonts from the internet.
- **Page 1, cover:**
  - "LexaVault" with the logo mark;
  - "Compliance report · summary edition" (or "· full audit trail edition");
  - customer name and entity name (if there is no customer name on the server, use the entity name alone and say so in the report);
  - the period in words;
  - Created by: display name and role;
  - Created at: in the requested time zone;
  - Entity: "<name> only. Other entities are never included.";
  - the Edition line;
  - Contents;
  - the "LexaVault keeps no redacted values." box, worded as on the canvas;
  - the fingerprint block (B4).
- **Pages 2–3:** sections 1–4 as on the canvas, with the "No redacted values are kept." box after section 2. Section 4 ends with the canvas's line about the full edition. In the full edition it instead says the appendix follows.
- **Every page:** a header line with the report, entity, period and customer; a footer with the short fingerprint, "created by LexaVault", and "Page N of M". The cover footer reads "Created by LexaVault · contains no borrower names, file names, loan numbers or redacted values".
- **Appendix (full edition only):** "Appendix · Full audit trail". One row per record in the period, oldest first: time, action (in the Admin › Audit trail sentence words), person (display name, or "LexaVault (automatic)" for the system), result, case ID.
  - **Detail column:** for each `AuditAction`, decide whether its detail is safe to print: counts, settings, codes and IDs only, never file names, borrower names, loan numbers, business identifier values, found text, or error text from outside. Print the detail only for actions on that allow list, otherwise print "—".
  - Put the allow list in one class with a test, and list it in the report.
  - The appendix may be long; it must page correctly. Test with 5,000 records.

**B4. Fingerprint** (design chat decision, see "Question for the owner" below).
- A file cannot carry its own SHA-256, so:
  - **Printed:** the **content fingerprint**, the SHA-256 of a canonical, ordered text form of every value printed in the report (including the created-at time, the creator and the edition). It is shown in groups of 4, on the cover in full and in the footer shortened.
  - **Saved:** `COMPLIANCE_REPORT_CREATED` (from 0016) is written with detail `period=<from>..<to>, edition=SUMMARY|FULL, fingerprint=<content hex>, fileSha256=<hex of the final PDF bytes>`. The response also carries the header `X-Report-File-SHA256`.
- **Cover text under the fingerprint:** "Fingerprint of this report's contents. LexaVault's audit trail records it together with the SHA-256 of this file, so the file can be checked against it."
- Audit refusals and failures too. Never put the PDF itself in storage: build it in memory or a temp file, send it, delete the temp file.

**B5. Never in the PDF, the audit detail or the logs:** borrower names, file names, loan numbers, business identifier values, found text or redacted values. Tests:
- **Report content:** create cases whose file names and business identifier values hold known markers, then search the extracted PDF text (PDFBox) for each marker, in both editions. 0 matches.
- **Leak checks:** extend `NoRedactedValueSavedTest`'s approach, or the 0015 script, so that creating a report is covered. The fake values must not appear in the PDF text either.
