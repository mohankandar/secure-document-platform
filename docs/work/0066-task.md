From `docs/work/v1-redaction-requirements.md`:
1. **BL1, Continue manually for a case stopped on an unreadable page (item 10).** Today "Continue manually" exists only for cases stopped at an AI step. Extend it: when Text stops a case because a page can't be read (OCR fails or the page is empty after OCR), a reviewer with the existing permission for Continue manually can choose, per unreadable page, **"Review this page by hand"** (the page goes to Review with no automatic findings, clearly marked "Unreadable: check by hand") or **"Remove this page"** (only if the policy allows removing pages; otherwise not offered). The choice and who made it are audited (page number only, never page content). The case then continues through Find and Redact for the readable pages. A case with all pages unreadable can only be continued page by page by hand, or rejected.
2. **BL8, rejection reason.** Every reject step (Review reject, Approval reject, the new unreadable-page reject) stores a **reason code** from a fixed list of `LV-` codes (add them to the error-code catalogue and its document: for example wrong document, unreadable, out of scope, duplicate, other-see-ticket), never free text. The Cases list and the case's history show the reason's plain name; the export/notification carries the code.
