## The owner's rule (decision, 2026-11-26)
**A sensitive value is found by what it is, not by the words around it.** Labels vary without end (form wording, old forms, other languages, OCR damage, no label at all), so a missing or unknown label must never let a value through. Labels may only **raise** confidence; they never decide whether a value is found. LexaVault must be more reliable than the big vendors' tools, not as good as them.

Concretely:
1. **Locked items (card, CVV, PIN) and SSN:** any value with the right shape and validity (card: 13–19 digits, an issuer prefix, the check digit; SSN: the valid number ranges; CVV/PIN: see 4) is **covered automatically**, with or without a label (replaces 0099 question 2's "to Review at 0.75": the owner chose to cover). A known false-alarm list (e.g. well-known test or sample numbers in a manual) is not an excuse; cover first.
2. **Every other enabled kind** (DOB, routing, account, ITIN, EIN, driver's licence, passport, credit score, names): a value that fits the kind's shape and validity (routing: ABA checksum; dates: a real date in a plausible birth range; etc.) and is **not clearly something else** is **covered or sent to a person**; never dropped because a label is missing. "Clearly something else" has to be shown by the document (the AI's reading of the sentence, a table header that names another thing), not by the absence of a label.
3. **The AI layer is asked for every enabled and locked kind on every page**, always, as a second reader; a value either layer finds counts. Where the two disagree, the case goes to a person.
4. **CVV and PIN** (3–6 digits look like anything): found next to a card number or card wording, in a card table, or by the AI; when a card number is on the page, every lone 3–4 digit number near it is held for a person.

## Steps
1. **Audit, written down first:** for each kind, every way it's found today (pattern, checksum, label, AI, vision) and every way it can be missed. Put the table in the report.
2. **A hard test set, built before the fix** (synthetic, made by script like `C:\dev\lexavault\test-pdfs\gen.py`): for each kind, values with **no label**, a **far** label, an **unusual or old** label ("Acct.", "Soc. Sec.", "Bnk Rte", "Card ending"), **another language** (Spanish), in **tables**, in **running sentences**, **split across lines**, with **OCR damage**, **handwritten** and in **images**. Plus decoys that must stay visible (order numbers, phone numbers, amounts, dates that aren't birth dates).
3. **Measure the misses per kind on today's code** (red first), then change the detectors to the rule above, then measure again. Target: **0 misses** for locked items and SSN; every other kind: no miss that wasn't sent to a person. Report false alarms per kind too, honestly.
4. Re-run the owner's 13 files and the long files; the benchmark gate (routed and all) must not get worse in misses.

## Prove it
The audit table; the miss and false-alarm table per kind before and after; the hard set added to the automatic tests; the no-redacted-value check.
