# 0114: LexaVault install proof

Queue A, after 0113, before 0051. Owner 2026-11-27. Model: platform-core P053 (monthly install proof, Linux and Windows, from published artifacts; failure opens an `install-proof` issue) and Vero's own proof.

**What it proves:** a customer can install LexaVault from the shipped package and the install guide alone, on a clean machine, with nothing from our development setup.

- Runs in GitHub Actions on a clean Linux and a clean Windows runner. It never runs on the owner's laptop.
- Uses only the build's release package (today the integration branch's artifacts; from 0088 on, the tagged release) and follows LexaVault's install guide step by step. If a step in the guide is wrong or missing, fix the guide, not the proof.
- Proves first-install criteria 11-15 where a machine can:
  - the schema is applied as a separate step with an admin account;
  - LexaVault then runs with an everyday-rights database account;
  - no secret is in the package;
  - one document goes end to end (sign-in with a throwaway identity provider, intake, redaction with the SIMULATOR AI since there is no GPU, review, delivery to a test destination);
  - stop and restart;
  - a backup and restore of the database on a test copy;
  - an upgrade from the previous build.
- Runs on every release, and monthly on a schedule. A failure opens an `install-proof` issue with the step that failed.
- Report: how long the install takes, and every guide fix.

Done when: merged on green CI, the first run green on both systems, TO-TEST.md entry (where to see the run), report.
