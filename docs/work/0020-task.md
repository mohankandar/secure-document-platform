## Part A: Safe policy follow-ups (frontend)

**A1. Save waits for an estimate that is on its way.**
- If the mode or threshold differs from the saved policy and an estimate request is waiting (the 300 ms delay) or running, pressing Save starts it at once if needed, then waits for it.
- While waiting, the save button reads "Working out…", the card's controls are locked, and a second press does nothing.
- When the answer arrives, the normal rule applies: the confirm step if fewer findings would go to a person, otherwise save.
- If the estimate fails or says not enough data, save without the confirm step, as now.
- Never save from an old answer that was for different values.

**A2. Confirm wording for Custom.** When the old or new policy is Custom, the buttons read "Keep your current settings" and "Save these settings". The other text uses "your current settings" / "these settings" in place of the name. The audit line still says "… as Custom → Light" (or similar).

**A3. Fine-tune wording.**
- The mode button "Every case" becomes **"Every finding"**.
- The hint under the slider in that mode reads: "Every finding goes to a person. Cases with nothing found are delivered without a check." In the other mode it stays "Findings below this go to a reviewer."
- Check every other screen that names this mode, for example the audit trail sentences, the compliance report wording ("Every case") and the U009 or Reports text. Use the same words everywhere, including `SensitiveTypeNames` / the PDF's section 1 "Sent to a person: Every finding". List each place you changed.

**A4. The confirm step against real data** (owner's answer 1).
- Run the UI against the 0019 throwaway environment (`test-tools/policy-estimate`, 21 real cases, saved policy as that script leaves it).
- Move to a setting that sends fewer findings to a person, see the confirm step with the real numbers, press Keep (nothing saved), then Save (saved).
- Pictures in `docs/work/ui/compare/U023/realdata-*` (not committed), plus the audit record.
- The throwaway container is removed afterwards. Shared data is not touched.

**A5. Tests** for A1–A3, in the existing suites. The confirm-step tests cover the Custom wording and save-while-waiting, including a slow estimate and a failed one.

## Part B: time saved (backend)

**B1. Definitions.** All are per entity, for the same period Reports already uses (its selected range and filters). Use the reporting package facts, so they agree with Reports' existing tiles.
- **Cases** (the denominator): cases first delivered in the period. This is Reports' "Delivered".
- **Handled without a person:** of those cases, the ones no person reviewed and that were not finished by hand: `reviewed_flag` is false, and there is no `BUSINESS_MANUAL_FALLBACK_SUBMITTED`. Return the count and the whole percent (rounded down).
- **Pages checked:** the sum of `page_count` over those delivered cases, and the sum of `document_count`.
- **Sensitive items redacted:** findings in those delivered cases with status CONFIRMED, by a person or automatically. Return the count, and the list of types that appear (for the tile's grey line, in vocabulary names).
- **Pages in cases that needed no person:** the sum of `page_count` over the "handled without a person" cases. Pages in reviewed cases count as zero.
- **Minutes saved:** that page count × minutes per page, **rounded down** to whole minutes.
- The response carries every input, so the "How is this worked out?" panel shows the real numbers: `pagesNoPerson`, `minutesPerPage`, `minutesSaved`.
- **Report the exact definitions.** If any of them disagrees with Reports' existing numbers for the same period, stop and ask.

**B2. Setting: minutes per page.**
- Migration `041-reporting-minutes-per-page.xml`: one column on `reporting_tenant_settings`, `minutes_per_page NUMERIC(4,1) NOT NULL DEFAULT 1.0`.
- Allowed: 0.5 to 30, in steps of 0.5. Anything else gives 400.
- Saved with the other report targets. The change is audited in `REPORTING_CONFIGURATION_CHANGED`, with the new value and `previous=`, in the same key style as 0016/0018. No record when nothing changed.
- `REPORTING_CONFIGURATION_CHANGED` is already on the appendix allow list. Check that the new detail still holds only numbers.

**B3. API.**
- Add the numbers to the existing Reports response (`GET /api/v1/operations/reports`) as one new block, for example `"timeSaved": { "casesDelivered", "casesNoPerson", "percentNoPerson", "pagesChecked", "documentsChecked", "itemsRedacted", "itemTypes": [...], "pagesNoPerson", "minutesPerPage", "minutesSaved" }`.
- Same capability as Reports' headline (`REPORT_EXECUTIVE_VIEW`), so the Business Administrator and the Report Viewer see it.
- `minutesPerPage` is also in the business-admin configuration read and save.
- With no delivered cases, every count is 0 and the percent is null.
- **Combined (all entities) view, if Reports has one:** add the counts up. `minutesPerPage` is null there, and `minutesSaved` is the sum of each entity's own minutes.

**B4. In the compliance report** (the design: "also printed in the compliance report").
- Add a small table at the end of section 3, "What LexaVault did for you", in the same table style.
- Rows: Handled without a person (count, % of delivered), Pages checked, Sensitive items redacted, Review time saved (estimate, "≈ N h" rounded down, or minutes under 1 h).
- One grey line under it: "Estimate: pages in cases that needed no person × <m> minutes per page, rounded down. Pages a person reviewed count as zero."
- These go into the content fingerprint.
- Use the period's numbers. Minutes per page is the setting as it stood at the period end, taken from the audit history like the other settings.
