# Report 0112: a case finishes after a person checks a page the final check held

Date: 2026-11-27
Branch: `feature/0112-held-page-resume`, from `origin/feature/lexavault-r1b-tenant-identity` at `7c56856`
Outcome: **DONE** (PR #54)

## Cause
The review moves the case to PROCESSING before it triggers it (`FocusedReviewService.resumeWhenDecided`). The staged pipeline then takes its PROCESSING path, and the gate queued the document's REDACT job without "again". That job already existed as DONE for this case run (the run the final check held), so queuing it added nothing: all jobs DONE, document REDACTING, case PROCESSING for ever. The existing test for a held page (0083) passed because it triggered the case while it was still PENDING_REVIEW, not the way the review does.

## What changed
- `StagedProcessingService`: a REDACT run that keeps nothing and leaves something for a person finishes with the detail `HELD_FOR_A_PERSON`. In PROCESSING, the gate runs a finished REDACT job again only when it waited for a person (`HELD_FOR_A_PERSON`, or the existing `WAITING_FOR_REVIEW`) and nothing is left for a person now. The run again is the full redaction: page checks applied, safety check, **final check** on the new redacted copy. Held again → back to Review; clean → Approval / export. Each run again needs a person's decision in between, so it can't loop.
- **Guard:** in PROCESSING, a document waiting for redaction whose REDACT run finished without waiting for a person (nothing planned) stops the case: FAILED (shown as **Stopped**), a package incident (`NOTHING_PLANNED`), an audit failure and an error log line `PIPELINE_CASE_NOTHING_PLANNED`, all with the new **LV-PRC-011** ("Processing stopped: nothing was planned"). Nothing is delivered. No timer: the gate decides when it runs.
- LV-PRC-011 added to the code list, the guide (`docs/api/error-codes.md`), the design table and the generated frontend file (regenerated by its tests).
- No schema change, no new dependency.
