## Rule (owner, 2026-11-20)

- Documents carry a sensitivity level: `STANDARD`, `CONFIDENTIAL` or `HIGHLY_CONFIDENTIAL`.
- The **source system** sets it on the **case (contract)**, on **each document**, or both. Nothing sent means `STANDARD`.
- LexaVault **never decides or changes** a level. It keeps what it was given and passes it on unchanged when it exports.
- The level does **not** limit anything inside LexaVault: every LexaVault user may see every case, because reviewers must see content to redact it.

## 1. Intake

1. **External intake API:** optional `caseSensitivityLevel` on the case and `sensitivityLevel` on each document.
   - An unknown or wrongly cased value is **never refused** (owner, 2026-11-20). The case or document is taken in as `STANDARD`, and a warning `LV-INT-005` "Unknown sensitivity level, taken as Standard" is recorded in the audit trail (the code only, never the value sent) so it can be counted later in Reports. The response is still a success; it may list the warning. The error code list will adopt the code.
   - Update the API spec.
2. **Scanner intake:** the same fields where the scanner integration can send them; otherwise `STANDARD`. Say what you found.
3. **Watched folder:** each watched folder gets a **level setting** (Tenant IT; default `STANDARD`). Every file picked up from it gets that level. Example: a migration folder set to Highly Confidential.
   - **Not in this task:** reading levels or document types from a **trigger file**. The owner's direction:
     - a trigger file always describes the whole folder drop;
     - its format differs per customer (XML, JSON or other);
     - each watched folder will later get a configurable "trigger file and where each value comes from" setting.

     That is a separate later task. Keep the code ready for it: the folder's level is a default that a later mapping can override.
4. **Manual upload (New case):** a **"Sensitivity"** choice for the case: Standard (default), Confidential, Highly Confidential. It applies as the case level. Plain wording, the same look as the other New case fields.
5. List every intake path you found and how each sets the level.

## 2. Storage

- Store the case level and each document level with the case. This needs a migration; give it the next number after the last one on the branch.
- The **effective level** is the higher of the document's level and its case's level. Compute it in one shared rule, with tests; Reports will use it.
- **Audit** records the levels received at intake (codes only).
- No redacted values are affected.

## 3. Export

- **Full-case export** (`SdvDeliveryAdapter` today) sends both levels with every export, using the field names of Vero's delivery API (Vero task 0024): `recordSensitivityLevel` and `sensitivityLevel`. Retries carry the same levels.
- **Split documents** (sending by barcode): every document cut from a source document carries that **source document's level**, plus the case level, to its destination. What the destination does with it is its own choice.
  - Destinations that can't receive a level: say which ones they are, and how the level is sent or noted for them (for example in the file's metadata or the delivery request). Ask before inventing a format.
- **A destination refuses a level (400):** a non-retryable export error, shown to IT Admin in Support, with the code `LV-DLV-003` "Destination refused the sensitivity level".

## 4. Screens (owner, 2026-11-20)

- **Case panel only:** one read-only line, **"Sensitivity: <effective level>, as sent by the source system"**. If a document's level differs from the case's, the document list in the panel shows that document's level next to it.
- No badge in the Cases list, in Review, or anywhere else; the level limits nothing in LexaVault. Nobody can change a level in LexaVault.
- The watched-folder settings get the level choice (section 1.3), and New case gets its "Sensitivity" choice (section 1.4).
