The owner tested by hand: dropping folders, changing contract numbers, running SQL in DBeaver, and the design chat checking the outputs. It worked but is slow and not repeatable. Each round must start clean and end with the same scorecard, so rounds can be compared.

## Build
1. **A fresh local test database, safely.** One command that starts a **throwaway** PostgreSQL (its own container and port, like `test-tools/intake-paths`) and runs LexaVault LOCAL against it, so a round starts from zero. **Never** touch, empty or remove the owner's protected containers (`securedoc-postgres`, `sdv-postgres`, `sdv-vault`, `lexa-keycloak`, `lexa-keycloak-db`) or his normal database; never delete audit or erase-log records by hand.
2. **The round:** copy the test set (`C:\dev\lexavault\test-pdfs`: the 13 files and `long\*.pdf`, as folder drops with manifests and fresh contract numbers per round) into the watched folder, wait until every case has finished or is waiting for a person, then **score before any person touches it**.
3. **The scorecard** (one Markdown file per round under `test-tools/owner-run/results/`, plus a short console summary), using the expected answers in `test-pdfs\README.md` and the `-expected.txt` files:
   - **leaks** per file: enabled or locked values still readable in the delivered file (text layer, OCR, **and the vision model for handwritten or image pages**, since OCR can't read handwriting);
   - **extra redaction** per file: words covered that aren't sensitive (compare original and redacted pages; ignore the TEST watermark);
   - **automatic %**, findings without a place, findings sent to a person, with their reasons (from 0105's new fields when present);
   - intake results (accepted, refused with code, waiting), unread pages, time per case.
4. A second mode scores **again after the owner's review**, and shows what the person changed.
5. A README for the owner: the one command, how long it takes, how to read the scorecard.
