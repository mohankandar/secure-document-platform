## Changes to the plan for Phase 2

1. **The CSV reader follows the usual CSV rules** (RFC 4180): quoted fields, a comma inside a quoted field, doubled quotes, CRLF or LF line ends, and a UTF-8 byte-order mark at the start are all accepted, because the file will be opened and saved in Excel. Do not forbid commas in group names: some login systems send group names that contain them. A line break inside a group name is still refused.
2. **Invisible differences are refused, not repaired.** A group, role or entity name with leading or trailing spaces, a non-breaking space, or a control character refuses the file with the line named. The loader never trims a value silently, because a group that almost matches is a sign-in fault nobody can see.
3. **A dry run.** `--dry-run` reads and validates the file, prints the same per-entity summary (to add, to remove, unchanged) and writes nothing. Installers run it with the customer before the real load.
4. **An empty result is refused.** A file with a header and no rows is refused. A file can never remove every mapping of an entity by omission of rows, because an entity appears only through its rows; say so in the command's help text.
5. **The audit record does not need the group names repeated**, only the counts, the file's SHA-256 and name, and who ran it, as planned.
6. **Format version.** Check the `Format:` comment after all: if it is present and is not `lexavault-role-mapping/1`, refuse. If it is absent, accept. That leaves room to change the format later.
7. **Template.** Add `docs/install/role-mapping-template.csv` with the comments explaining each column and one worked example for two entities, and a half-page `docs/install/ROLE_MAPPING_FILE.md`: how to fill it in, how to dry-run, how to load, what each refusal message means.
