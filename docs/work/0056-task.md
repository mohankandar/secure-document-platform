# Task 0056: LexaVault on Spring Boot 4.2 and platform-core v0.8.1

Written 2026-11-24 by the LexaVault design chat (owner approved Spring Boot 4.2, board LV-18). Queue task. Large. Standing rules (`QUEUE.md` rule 8). Report: `docs/work/0056-report.md`.

- **Why:** Spring Boot 3.x is past open-source support. Platform-core moved to Spring Boot 4.2 (`v0.8.0`) and posted **`platform-core-v0.8.1`** as the version apps pin for their move (board SH-28; release notes `docs/releases/platform-core-v0.8.0.md` and `v0.8.1.md` in platform-core, with a migration checklist; read them, read only).
- **Scope:** only the Spring move and the platform-core bump that goes with it (identity modules and their helpers, exactly the set 0054 allowed; the setup jar). **No feature change**, no other capability of platform-core enters the app.
- **Order:** after 0054 (identity on `v0.7.0`, Boot 3). Branch from the integration branch once 0054 is merged.
- **Owner approvals given:** Spring Boot **4.2.x** (newest patch) with Framework 7.1, Security 7.2, Hibernate/JPA as Boot 4.2 manages them, Jackson 3, Java 21; the dependency changes the move needs (listed in the report); identity schema migrations `v0.8.1` brings (schema step, never at startup). If a library LexaVault uses has no Boot 4.2-ready version, **stop and describe it** (the 4.1.x fallback is the design chat's decision).

1. Backend on Spring Boot 4.2.x and `platform-bom` `0.8.1` (from GitHub Packages); Boot 4's split starters and auto-configuration names; `javax`/old APIs replaced; Jackson 3 (no Jackson 2 left in LexaVault's own code; say if a library still pulls it); Spring Security 7 configuration; Hibernate 7 and Liquibase as Boot 4.2 manages them (keep Liquibase open-source 4.x if 5.x's licence is unclear; say which).
