# Task 0053: Detection reads form-field values (no sensitive value left in a form field)

Written 2026-11-24 by the LexaVault design chat. Queue task, **next after 0050** (before 0051). Found in 0050: text in a visible form field is not read by detection, so a sensitive value that appears **only** in a form field is never found; 0050 flattens the field into the page's drawing, so the value stays visible in the output. This is a leak and is fixed now.

- **Owner approvals given** (design chat, as recommended under LV-19): this change in detection and extraction (V1 processing, frozen) for exactly what is described here. No migration, no new dependency. Standing rules (`QUEUE.md` rule 8). Report: `docs/work/0053-report.md`.

## Build
1. **Extraction reads form-field values** (AcroForm text fields, combo/list choices, and the text drawn in their appearance), on the page where the field is shown, with the field's box as the position, and gives them to detection exactly like page text. Checkbox/radio states are not text and are ignored.
2. **Detection and redaction treat them like page text:** a finding in a field is redacted on the page (box over the field's area, page burned flat as for any redaction), then 0050's flattening and removal run.
3. **The whole-file final check** (0044/0050) already covers the flattened appearance streams; add a test proving a field-only SSN is now found, redacted and absent from the output.
4. XFA forms (if PDFBox exposes them): if a document has XFA content that can't be read, the document stops with a clear `LV-` code (fail closed) rather than passing unread. Say what you found.

## Prove it
Test PDFs (fake values) with an SSN only in a text field, a card number only in a combo box, and a mixed page: each is found, redacted and absent from the output bytes; pages without fields unchanged. Full backend build with PostgreSQL tests on, `npm run test:standalone`, the no-redacted-value check, the compliance report check, the export end-to-end, the product-name guard; the benchmark's 26 PDFs give the same results as 0050.

## Addendum (2026-11-24, design chat, decided as recommended under LV-19; from 0050's question)
**Annotations too:** text in free-text notes, stamps, callouts and any other annotation whose appearance 0050 draws into the page is read by detection the same way as form fields (position = the annotation's box), and redacted if it holds a finding. Same tests: a value only in a free-text note and only in a stamp is found, redacted and absent from the output. If this task is already past that point, do it as the last step before the report.
