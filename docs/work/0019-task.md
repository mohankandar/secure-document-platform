## Part B: the policy estimate

**B1. Check the real rule first, and report it.** From `SensitiveDataDetectionService` and wherever a case's review need is decided, state exactly when a finding goes to a person and when a case does.
- As read by the design chat:
  - a finding is auto-confirmed only in `UNCERTAIN_ONLY`, with confidence ≥ the threshold and a bounding box; every other finding waits for a person;
  - a case needs a person when any finding waits.
- **Check in particular:** under `REVIEW_ALL`, does a case with no findings go to a person, or straight through? The canvas says Strict means "Every case goes to a person" and counts every case. If cases with no findings go straight through, the estimate must follow the code, not the canvas. Say so plainly in the report: the Strict wording is then the owner's decision.
- Also say whether manual-region findings and OCR-guard or unlocated findings behave differently.

**B2. Endpoint.** `GET /api/v1/business-admin/sensitive-data-policy/estimate?reviewMode=…&threshold=…`, needing `TENANT_POLICY_MANAGE` (Business Administrator). The values are checked like a save: mode required; threshold 0.50–0.99 (ignored for `REVIEW_ALL`).
- **Window:** cases (packages) of the signed-in entity received in the last 30 days, up to now.
- **Counts, both under the current saved policy and under the proposed one, worked out the same way from stored finding records** (type, confidence, whether located, status source). Never use the actual history, so both sides are comparable:
  - cases a person would check;
  - findings a person would check.
- Leave out findings a person made by hand (manual regions). They don't depend on the policy.
- **Response:**
  `{ "windowDays": 30, "cases": N, "enoughData": true, "current": { "reviewMode", "threshold", "preset", "casesToPerson", "findingsToPerson" }, "proposed": { same } }`
  - `preset` comes from `PolicyPreset`.
  - Under 20 cases: `enoughData: false`, the case count, and no other counts.
- The estimate covers only the review mode and threshold, not changes to the sensitive types: it uses the findings that exist.
- **Counts only.** It never reads found text, files, file names or business identifiers.
- Reading the estimate is not audited.

**B3. Speed.**
- It must answer in under 1 second for an entity with 2,000 cases and 50,000 findings in the window.
- Do it with aggregate SQL, not by loading entities.
- Test it on a throwaway database with that volume. Show the query plan in the report.
- If an index is needed to meet that, stop and ask.
