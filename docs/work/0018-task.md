## Steps

**A1. Customer name.** When a licence is installed, its `customerName` (`LicenseClaims`) is the customer name on the cover and in the header line. Without a licence, show the entity name alone, as now. The cover stays without a header line (answer 1). Test both cases.

**A2. Every refusal is recorded.**
- `CapabilityAuthorizationInterceptor` writes a DENIED audit record for every 403 it returns: the existing `AUTHORIZATION_FAILED` action, with detail `capability=<missing capability>, method=<HTTP method>, route=<route pattern>`.
- Use the route pattern (for example `/api/v1/compliance-reports`), never the actual URL, query string or request body.
- Don't record a request twice where the endpoint already writes its own DENIED record (compliance report, vault download).
- Add `AUTHORIZATION_FAILED` to the appendix detail allow list. Test it.

**A3. Hide the "Rejected" rows.** Remove "Rejected by a supervisor" (section 3) and "Cases rejected" (section 4) from the PDF and from the content fingerprint. Remove them in one place, so they are easy to bring back once rejecting a case exists. "Still open" and the shares stay as now.

**A4. Lifecycle history.**
- `LIFECYCLE_POLICY_CHANGED` detail gets `previous=[…]`, or `previous=none`, exactly like the sensitive-data policy (0016). The existing keys stay first and unchanged.
- The report reads the previous values from that key when it is there. It falls back to today's rebuilding logic for older records.
- Section 2 shows a "Changes during the period" table (When / Who / What changed), worded like section 1. Examples: "Originals kept for: 72 → 48 hours", "Supervisor approval before delivery: Required → Not required". Show it only when there were changes.
- Test both the new and the old record formats.

**A5. Note under section 3.** Under the first table add, in the canvas's small grey text: "Delivered counts cases first delivered in the period, whenever they were received, as on the Reports page. Shares are of cases received." Put the note in the content fingerprint too.

**A6. Polling clients are named.** Polling runs record `Polling: <connection name>` as the display name for the run's records. They run on a scheduler thread, so pass the name explicitly through the `AuditService` overloads, or bind it for the run and clear it in a `finally`. Never leave it bound on the thread afterwards. Test that a later record on the same thread gets no name.

**A7. Footer spacing.** The short fingerprint in the footer has a double space ("cacc  4c84"). Make it a single space, and check that the cover's full fingerprint spacing is still right.

**A8. Tests and checks.**
- Full backend and frontend builds.
- Rerun `test-tools/compliance-report/Invoke-ComplianceReportCheck.ps1`, updated for A1–A5, and `test-tools/no-redacted-values/Invoke-NoRedactedValueCheck.ps1`.
