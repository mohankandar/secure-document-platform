## 1. Page batches for Text and Find
- A document over the batch size is split into **page batches** for Text and Find (`pipeline_jobs` page range from 0048); batches of one document run in parallel and are gathered before Redact.
- **Batch size and overlap are redaction-policy settings** (defaults: **20 pages, 2 pages overlap**). Findings in the overlap are merged by their place on the page (one finding per box), as Find does today for duplicates.
- A document up to the batch size is one job, exactly as in 0048.
- Prove: a 500-page synthetic document spreads over the workers; findings across a page break are kept; no finding is doubled in the overlap; the result equals the whole-document run on the same pages (same findings and boxes).

## 2. Fairness between entities
Within the same stage and priority, workers **take turns between entities** (oldest first within each entity), so one entity's flood never pushes another's work back. Prove: entity A queues 200 documents, then entity B queues 5; B's documents start within the next few claims, not after A's 200.

## 3. AI requests at once
A setting for the number of AI requests at once per AI server (default **2**), used by the Find workers' limit, and set as `OLLAMA_NUM_PARALLEL` by the local start scripts (`Start-LexaVault-*.ps1` / `.sh`) when they start or warm Ollama themselves (they don't restart an Ollama the owner runs; they say so if its setting differs). The learned limit is P3, not this task.

## 4. Switching back from staged to inline
When `pipeline-mode` goes back to `inline`, the stage workers **keep finishing the staged jobs already queued**; only new cases go inline. Prove it: switch mid-run, every staged case still finishes, nothing is processed twice.

## 5. Clean-up sweep for files with no record
A sweep (inside the existing lifecycle maintenance, like 0034's job clean-up) removes stored **text and redacted files that no record points to**, older than a safe delay (setting, default **24 h**), for both flows. One audit record per run with counts only. Never removes a file a record points to, or one younger than the delay. Prove it with a file left by a killed worker.
