## Part B: leaks (the inventory's "can show content or a secret" list)

Rule: no document text, redacted value, file name, folder name, person's name, host with credentials or secret in any screen, API response, audit detail or log. Where a reference is needed, use an id or a code.

1. **Polling raw exception text** (#34): store and show a code and the exception **type** only, never its message. Keep every failure of a run, not only the last; a partly failed run is not SUCCESS.
2. **Echoed source ids and file names** (#49, #55): messages say what is wrong without the value.
3. **Watched-folder observations and logs** (#39, #56–#61): no drop-folder names or absolute paths on screen or in logs. Use the folder key plus a short drop id (for example a hash prefix) that IT can match on the server.
4. **Local-folder and file-share delivery** (#200, #201, #222): no file names or full paths in the export record, responses or Technical details. The case panel fallback label uses the document id or type.
5. **`IllegalStateException` text to the screen** (#291, #383, #167–#172): the API sends a fixed message per error code; the raw text goes to the log only, and only if it cannot hold content.
6. **OIDC discovery test** (#241): show a short category ("could not reach", "not valid JSON", "HTTP <status>"), not raw remote text. **IdP token error body in the browser console** (#277): remove, or development builds only.
7. **Business-admin validation** (#286): no inner exception message to the screen.
8. **AI pool node URL in the start-up error** (#328): strip any user info from URLs before logging.
9. **Content left on disk after a failure** (#370, #372, #373, #86, #91): make sure temp PDFs, OCR folders and redacted temp output are deleted on every path (finally blocks), and that a failed delete is logged with the temp-file **id** (no name) so IT can clean up. Simulator rejects must not keep the original name.
10. **Scan Bridge identifiers on disk** (#83) and **the no-access screen showing the user's email** (#284): do not change; describe in the report what would be needed.

## Part C: silent failures

1. **Endless processing re-dispatch** (#346, #358), frozen-area change approved: after **3** failed dispatch attempts of the same case, stop it as FAILED with a technical failure code and a Support incident. A licence denial stops at once (no retry), with its own code, one audit row, not one per pass. Keep everything else in the V1 flow unchanged.
2. **Watched folder catch-all** (#38, #61, #39): record the **real reason** for each refused drop (identifier, licence, capability, inactive tenant, storage, malformed trigger, IO) as a code in the audit and the observation, not `SOURCE_IO_ERROR` for all. A duplicate drop writes a record (#41).
3. **Processing failures with no incident** (#137, #142, #367): a confirmed finding with no location creates an incident; redaction verification keeps its exact reason as a code; a failure to save an incident is logged.
4. **Split delivery** (#181, #192, #189, #190): routing failures and automatic-send refusals are audited with a code and appear in the attention list. Do not add retries.
5. **Sign-in refusals** (#239, #252, #236, #266), frozen-area change approved, LexaVault side only: every admission refusal writes `SECURITY_CONTEXT_INVALID` (or `AUTHORIZATION_FAILED`, whichever fits) with a **reason code** and logs it; a rejected token logs the reason (issuer, audience, signature, expiry) and the 401 carries a correlation id. The user still sees only the safe message. **If the refusal happens inside the shared identity library, do not change the library:** list those places in the report for the Shared Capabilities thread.
6. **Audit rows rolled back with the request** (#308, #28): write a test first. If confirmed, write those audit rows in their own transaction.
7. **Errors replaced or not logged** (#290, #293, #291, #331, #357, #62, #110, #134, #131, #118, #333–#335, #337, #336, #338, #296, #340, #348, #325, #327): log the exception type and a code (never content). Where an admin message was written for the person, send it (it must not contain content).

## Part D: bugs

1. **Client mistakes return 500** (#7, #32): a missing `Idempotency-Key` or `X-Content-SHA256`, a missing file part, a wrong content type or a null identifier value return **400** with a clear message, as the intake documentation says.
2. **The Scan Bridge retries forever** (#82): do not retry 4xx; cap 5xx retries (3, spaced) and then mark the item failed so a person sees it.
3. **Push size limit** (#5, #22): the push source default must not exceed the multipart limit (both 50 MB); an empty file gets "The file is empty".
4. **Manual upload PDF check** (#45): check on the server that the file is a readable PDF, the same check machine intake uses.
5. **Review "already decided by someone else"** (#160): make the backend send one code for this conflict and the Review screen recognise it, so the person moves on with the right message.
6. **Lost processing lease** (#342): do **not** fix (frozen area, not approved). Describe the risk and the smallest fix in the report.
