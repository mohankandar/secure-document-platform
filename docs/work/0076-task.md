Written 2026-11-24 by the LexaVault design chat. Queue B. Standing rules (`QUEUE.md` rules 8–11). Owner approvals given for what this task describes, including migrations (07x). Design source: the project doc `claude/UI-Enhancements-Design.md` #5 (if a detail there conflicts with this file, follow this file and say so in the report).

Only when approval before delivery is on. In the approval list, a Supervisor can tick several cases (one entity at a time, up to 50) and **Approve selected**. **Four-eyes rule:** a case the approver reviewed themselves is not selectable (shown greyed with the reason); nobody approves their own work. A confirmation lists the cases by primary identifier and count. Each case is approved, audited and exported **as its own action** (one audit record per case, the bulk action named); if one fails, the others still go and the failed one stays with its reason. Bulk reject is out of scope (reject stays one case at a time, 0071).
