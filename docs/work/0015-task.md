# Task 0015: no redacted value is ever saved

Written 2026-11-19 by the design chat. Build plan step 1 in `docs/work/ui-enhancements-design.md` (rule: "No redacted value is ever saved by the application"). A safety fix; it goes before the other enhancements.

- **Base:** `feature/lexavault-r1b-tenant-identity` @ `72ded83`.
- **New branch:** `feature/no-redacted-values`.
- **Report:** `docs/work/0015-report.md`.
- **Owner approvals already given for this task** (CLAUDE.md "Ask before"): the schema change in A3, and the small change to detection code in A2 (a frozen area: V1 document processing). Nothing else in a frozen area may change. No new dependency.

## What the code does today (checked by the design chat)

- `findings.snippet` (VARCHAR 255, migration 002) is written from `DetectedEntity.maskedPreview` through `Finding.snippet` → `FindingEntity.snippet`.
- Only `LocalRuleBasedDetectionAdapter` puts real characters in it: `maskSsn` (`***-**-6789`), `maskPhone`, `maskDob` (year), `maskCreditCard` (last 4) and `maskEmail` (first letter of name and domain, plus the ending). The AI, OCR-guard and unlocated paths already save `***`; manual regions save `null`.
- **Nothing reads the snippet** for display: no API, report or UI uses it. No test references it.
- The Review queue's last 4 is **already read live** from the stored extracted text by `ReviewFoundTextReader` (fails closed, logs reason codes only). The UI masks it in `studio/reviewRules.ts`.
- AI log lines in `securedoc-ai` print counts, pages and failure codes, not text. The parser rejects with a fixed message.
- Migrations end at 038; `feature/phase2-role-mapping` adds none after 037, so **039** is free on both branches.

## Steps

**A1. Remove the snippet from the code.**
- Remove `snippet` from `Finding` (fields, factory methods, `reconstitute`, getter) and `FindingEntity`, and its mapping in `JpaFindingRepositoryAdapter`.
- Remove `maskedPreview` from `SensitiveDataDetectionPort.DetectedEntity` and every place that builds one.
- Remove the mask functions from `LocalRuleBasedDetectionAdapter` and the `MaskFunction` interface. The raw match is used only for offsets, as today.

**A2. Keep detection and redaction behaviour exactly the same.** Only the saved preview goes away: types, pages, offsets, boxes, confidence and decisions must not change. Prove it with the existing detection and redaction tests (all pass, unchanged) and say so in the report. If any of them needs changing beyond removing the preview argument, stop and ask.

**A3. Migration `039-findings-drop-snippet.xml`** (register it in the master changelog after 038):
- changeSet 1: set every `findings.snippet` to NULL;
- changeSet 2: drop the column.
- No rollback that recreates values. Run it on a throwaway database only (see A6), never against `securedoc-postgres`.

**A4. Guard the transient value holders.** Records that carry the found text in memory (`DiscoveredSensitiveContent` in `SensitiveContentAnalysisPort`, `SensitiveDataValidationPort.Candidate`, and any similar record you find) get a `toString()` that prints type and page only, so a stray log line cannot print the value. Check that the JSON parsing of the AI answer cannot put the answer's text into an exception message that is logged or saved (for example Jackson's source-in-location). Fix it if it can, and say what you found.

**A5. Review after the original is gone.** Confirm (and add a test if missing) that when the extracted-text artifact is no longer available, `ReviewFoundTextReader` returns nothing and the queue item shows type and page only. No UI change is expected; if one is needed, stop and ask.

**A6. Security test: a known fake value never appears, in full or in part.**
- Pick fake values the detectors accept: a test SSN, a test card number (for example `4111 1111 1111 1111`) and a date of birth. Choose them so their last 4 is easy to search for.
- **In the JVM (no new dependency):**
  - run the detection service over a page holding those values with the rule-based detector **and** a fake AI adapter whose answer contains them;
  - assert no saved `Finding`, `FindingEntity` or audit record holds the full value, the digits only, or the last 4;
  - capture all log output (Logback `ListAppender`, already on the classpath) and assert the same for every line.
- **End to end, scripted** (`scripts/` or `test-tools/`, PowerShell):
  - start a throwaway Postgres container (not one of the containers listed in CLAUDE.md), run the migrations, and take a `pg_dump` before any processing;
  - process a test PDF holding the fake values through the normal path, with the AI switched on through the mock Ollama;
  - dump again, and search the new dump, the app log files and the audit export (`/api/v1/audit-records/export`) for the full value, the digits only and the last 4, compared against the first dump so unrelated matches don't count;
  - remove only that container.
- Record both results in the report.

**A7. Build and test.** Full backend build and tests, and the frontend tests. Give counts per module (last known: 453 backend, 241 frontend).

**A8. Commit** on `feature/no-redacted-values`, with this task file, the report, and `docs/work/ui-enhancements-design.md` (the design doc copy, already in the folder). Do not push or merge.
