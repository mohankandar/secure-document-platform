From `docs/work/v1-redaction-requirements.md` (full text in the project doc `Redaction-Capabilities.md`):
1. **Item 2, new V1 pattern types:** bank account, US routing number, driver's licence, passport, tax ID (EIN/ITIN). Use **check digits** where they exist (Luhn for cards, the ABA routing checksum, invalid SSN ranges such as 000/666/9xx and 00 groups) and **nearby labels** ("Routing", "Acct", "DL#", "Passport No.") to raise confidence, so random digit runs aren't flagged. Each new type is an entry in the redaction catalog from 0062 (detection method, default style) and is placed in the right regulation packs (GLBA/Financial: bank account, routing, tax ID; others as `Redaction-Capabilities.md` says). Driver's licence formats: the common US state formats only, documented as such.
2. **Item 5, digitally signed PDFs:** processed as any other; the broken signature is expected. Record in the audit trail and the compliance report "Original was digitally signed; the signature no longer applies to the redacted copy" (signer name only if the PDF shows it in plain view, never certificate details). Nothing is added to the page.
