# Task 0044: R2 part 1, searchable redacted pages (option B)

Written 2026-11-22 by the LexaVault design chat. Part of the overnight queue. Branch `feature/0044-r2-searchable` from `feature/0043-r1-patterns`.

- **Report:** `docs/work/0044-report.md`.
- **Design (owner's choice B, 2026-11-21):** `docs/work/v1-redaction-requirements.md`, "Design decision for item 6". Today a page with a redaction becomes a 150-DPI image with no text (`PdfBoxBurnFlatRedactionAdapter`). Option B: keep the image page, then **add an invisible text layer made by OCR of the already-redacted image**, so the burned-in boxes can't leak into the text; the final check verifies it.
- **Owner approvals given:** option B in the redaction output (V1 processing, frozen, approved for this change only). No migration. No new dependency (use the Tesseract already used; if a new one seems needed, stop and describe it).
- **Independence rule** and the standing rules apply. **No redacted value is ever saved, logged or shown.**

## Build
1. After a page is burned flat, OCR the **redacted image** and add the words as an invisible text layer positioned over their image location (standard "image + hidden text" PDF), so the page is searchable and copyable.
2. **The final check is extended:** before a document is marked ready, the text of every output page (original text on untouched pages, the new layer on redacted pages) is checked; **if any value that was redacted appears in the output text, the document fails closed** (no export) with a clear `LV-` code and a Support explanation that names no value. The check compares in memory and saves nothing.
3. A setting per entity, **on by default** (`searchable redacted pages`), so a customer can turn it off and get today's image-only pages. Off = exactly today's output.
4. Untouched pages are unchanged by this task (hidden-content clean-up of untouched pages is a later R2 task).
5. The page stays 150 DPI unless OCR quality needs more; if you change it, say why and give the file-size effect.

## Prove it
- Tests with fake documents: a redacted SSN, card number and date of birth never appear in the output text (in the text layer, in copied text, or anywhere in the PDF bytes); the rest of the page's words are searchable; turning the setting off gives byte-for-byte today's behaviour (or say exactly what differs and why).
- A deliberately planted leak (test only) makes the final check fail closed.
- Full backend build with PostgreSQL tests on, `npm run test:standalone`, **the no-redacted-value check** (it must still find 0), the compliance report check, `scripts/Test-LexaVault-ExportE2E.ps1`.
- Timing: seconds per redacted page added, measured on the benchmark's 60-page package.
