# 0109: Hardening of two settings

Queue B, owner-approved 2026-11-27. (Short form for the repository.)

## Part 1: hardening: LOCAL mode only in development builds
- A production build asked to start in LOCAL mode refuses to start, whatever else is set, with one log line and an LV code
  ("LOCAL mode is only available in development builds").
- One shared check of what the build is, used by the sign-in setup (`SecurityConfig`) and the stored-file check
  (`FileProtectionConfig`).
- `start-local.cmd` / `Start-LexaVault-Local.ps1` (development build) work as before.
- Tests: production build with LOCAL mode does not start (with and without a key service); development build starts;
  production build with normal sign-in starts.

## Part 2: hardening: secret references limited to approved names
- Integration secret references follow the same rule as `AppSecretResolver`: only approved names; anything else is refused.
- One shared resolver; the per-adapter copies are removed (polling source, derived-document destination; the destination
  profile path already used the rule).
- A refused reference: the connection is not saved (or, if already saved, does not run), with an LV error naming the field,
  never the value. Nothing is sent.
- Existing connections with approved names work unchanged; any saved connection with a refused name is listed in the report.
- Tests: approved name resolves; unapproved `env:` and `sys:` names refused on save and at run time; no value in any log,
  error or audit detail.

## Done when
Both parts merged with green CI, a TO-TEST entry, and the report lists existing connections with refused names, if any.
