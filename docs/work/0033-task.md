Written 2026-11-21 by the LexaVault design chat, at the capabilities thread's request.

- **Report:** `docs/work/0033-report.md`.
- **Requirement:** `docs/work/vision-routing-requirement.md` (section 5) and `docs/work/v1-redaction-requirements.md` (item 8).

- **Git:** work on `feature/0033-vision-benchmark`, which you create from `feature/lexavault-r1b-tenant-identity`. Commit the harness and the report only. Do not merge or push.

## Privacy rules (hard)
- **Sample documents never enter the repository**, a log, the report or a picture. They live in a folder outside the repo that the owner names (default `C:\dev\benchmark-samples`, with `public\` and `customer\` subfolders). The harness only reads them.
- The report holds **numbers only**: counts, seconds, rates, per document type. **Never** a found value, a page image, a file name of a customer sample or any text from a document. Refer to samples as `customer-01` … in the report.
- **First-customer samples are used only with the customer's approval, or inside their environment.** If the `customer\` folder is empty, run part A only and say so.
- Models run **locally** (Ollama on this machine). Nothing is sent to an internet service.

## What to measure
For each page of each sample:
1. **Routing** (the rule in `vision-routing-requirement.md` section 2): would this page go to the fast text path, the fast path plus signature detection, or vision? Use what can be measured today: OCR confidence (Tesseract, as LexaVault runs it), whether the page has a text layer, whether text layer and image disagree, a simple detector for images, photos and IDs, and a handwriting check. Write down how each check was made.
2. **Text path** (as LexaVault does today: text layer or Tesseract, then the current patterns and the current text model): what is found.
3. **Vision path** on the routed pages only, with **2 or 3 local vision models** that run on this GPU (for example Qwen2.5-VL 7B, Llama 3.2 Vision 11B, MiniCPM-V; check each model's licence for commercial use and record it). The same prompt for each; the model returns item types and boxes, never kept beyond the comparison.
4. **Ground truth:** each sample comes with a hand-made answer file listing the sensitive items per page (type and rough box, **no values**). For public samples, make it yourself; for customer samples, the owner provides it.

## Report per model and overall
- Seconds per page (text path, vision path), pages routed to vision per package, and the **estimated seconds per document** for a 60-page package with that routing.
- **Misses** (items in the ground truth not found) and **false flags** (found, not in the ground truth), by item type and by page kind (typed, handwritten, ID, check, fax).
- GPU memory used, and the most requests at once that stayed fast.
- **Recommendation:** the model, the OCR-confidence threshold for routing, and whether **the 60-second-per-document target** holds (30 seconds better).

## Part A now: public samples
Build a set of **public or synthetic** samples with **fake data only** (for example forms with handwritten fake values, fake IDs and checks you generate, fax-like scans made by degrading clean pages). Record each source and its licence. Aim for 20–30 documents covering the page kinds above. Run the full benchmark on them.

## Part B later: first-customer samples
The same run on 20–30 first-customer samples once the owner places them (with approval) and their answer files in `customer\`. The harness must run part B with one command and no code changes.

## Report
The usual sections: what was built, the sample set (sources and licences, no content), the numbers, the recommendation, and questions for the owner. Commit on `feature/0033-vision-benchmark`. Do not merge or push.
