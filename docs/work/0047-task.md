## 1. Move the "Searchable redacted pages" switch
It is stored today as a row in `tenant_redaction_kinds` (meant for redaction kinds). Migration 048: a proper per-entity setting (a column on the entity's redaction policy table, default **on**), copy existing values, remove the row kind, with a rollback and a PostgreSQL test. API and screen unchanged for the user.

## 2. Final check re-reads only pages with findings
The 0044 final check re-reads the original's text for every page (13 s extra on the 60-page package, scanned pages OCR'd again). It needs the redacted values only from **pages with findings**: re-read those pages only, and still compare **every** output page's text against those values. Measure before/after on the benchmark's 60-page package.

## 3. SSN or ITIN on one box: ITIN wins
When both kinds are on and one value matches both, keep **one** finding: ITIN (an SSN never starts with 9). Tests for both orders and for each kind alone.

## 4. Driver's licence needs a driver context
"License number" alone no longer counts. Require "driver", "driver's license/licence", "DL", "D.L." (or the state DMV wording) within the label window. Tests: "business license number", "contractor license", "marriage license" are not flagged; "driver's license no." and "DL #" are.

## Prove it
Full backend build with PostgreSQL tests on, `npm run test:standalone`, the no-redacted-value check, the compliance report check, the export end-to-end, the product-name guard, and the benchmark's text-path numbers for the new kinds (to show item 4 doesn't lose real driver's licence numbers).
