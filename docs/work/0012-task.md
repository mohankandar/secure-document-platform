## Steps

Every step: full build, all tests, one commit. Follow the plan (`docs/work/0010-plan.md`, section 6) with these additions.

**P2a. Pin the branch.** Add resolver-level tests for the shared-issuer branch of `RequestContextResolver`, with the setting on: one entity, two entities with and without a selection, a selection the person does not hold, no entity, an inactive entity, a forged selection, the machine path with one and with two bindings, and the platform-role refusal. Run them against the old code. Commit.

**P2b. Switch.** `RequestContextResolver` and the discovery controller use the library. Add the wiring class. Delete the moved classes, their old tests and the parity test. The P2a tests and every other existing test must pass without being edited.

Then the **Phase 1 proof**: `Start-Phase1.ps1`, the 60 scripted checks, the browser script.

**P3. Actor ids.** Before replacing `TrustedActorResolver`:
- a test proves `StableIdentityId` gives the identical id for a set of realistic issuer and subject pairs, including the four Phase 1 users' real issuer and subject values and the golden id from L0;
- read the actor ids already stored in the Phase 1 database's audit records and confirm the library produces the same ids for those users (print counts only, no token or secret);
- a test records the one accepted difference: values padded with spaces.

Then replace it, and run the **Phase 1 proof** again. After the proof, confirm that new audit records for the Phase 1 users carry the same actor ids as the earlier ones.

**P4. Remove `OidcAudienceValidator`.** `JwtBoundaryTest` uses the library validator.

**L5. Release the library.** Only if every step above passed:
- version `0.3.0`; README entry; the schema contract page (the columns a product must provide for the four interfaces);
- merge `feature/admission-0.3.0` into `main` as a fast-forward, tag `v0.3.0`, push `main` and the tag.

**P5. Pin and prove.** LexaVault depends on `0.3.0`. Full backend build, `npm run test:standalone`, and the **final Phase 1 proof**. Push `feature/phase1b-identity-library`. Do not merge it; the design chat reviews it first.

Leave the Phase 1 backend and UI stopped and the containers kept, as before.

## Stop conditions

Stop and report, without working around it, if:
- a P2a test or any other existing test has to be edited to pass after the switch;
- any Phase 1 check or browser step fails;
- any actor id differs for an unpadded value, or a stored actor id does not match;
- one of the 11 original library classes has to change.

If a stop happens after the library branch is ahead, leave both branches as they are and do not release.

## To report, not to change

- Wording in the library's refusal messages that names LexaVault things (for example "tenant", "Platform Operations"). List them. The product should own the words and the library the reasons; that is a Phase 2 change.
- Anything in `RequestContextResolver` that is now dead or simpler than it needs to be.
