# 0116: Outages wait, they never stop a case (owner design 2026-11-27)

**PHASE 1 ONLY (owner 2026-11-27 22:00):** the AI servers (text and vision) only. Reuse LexaVault's existing "destination paused" mechanism for deliveries (pause, one alert, resume by itself) instead of building a new one. Database and storage outages are a later phase, not this task. Keep the change small; list anything you would add but did not.

Queue A, after 0110 (before 0113). Owner rule: the product handles IT trouble by itself; a person sees a case only when a person is truly needed.

## Three kinds of failure
| Kind | Examples | What LexaVault does | Who sees it |
|---|---|---|---|
| **A. Outage** (temporary, IT) | AI server down, network glitch, database restarting, storage briefly unreachable, timeouts under load | The case **waits** ("Waiting: AI server unreachable") and **resumes by itself**; no limit on tries while the dependency is down (bounded only by the 7-day keep rule, 0115). Never Stopped, never counted against the 3 step tries. | IT only: **one alert per outage**, not per case. Business users see a banner on Cases: "Processing paused since 21:40: AI server unreachable · 37 cases waiting". |
| **B. Document problem** (business) | a page nobody can read, even vision; a value found with no place; a damaged or unusual PDF | **That page/finding goes to Review**; the rest of the case continues | Business user, **Needs you** |
| **C. Our defect** (rare) | unexpected error; a value still found in the redacted copy | **Stopped**, with a diagnostic bundle (no document content) | IT (and the vendor) |

## How A is told from B
- Health checks for the AI servers (text and vision), database and storage, with a circuit breaker per dependency.
- A failure while its dependency is unhealthy = A: pause that stage for all cases (not per case), resume when healthy.
- The same page failing while the dependency is healthy = B (after the normal tries).
- Anything else unexpected = C.

## Alerts (IT Administrator settings, per installation; IT decides, not the business)
- Outage: warning after **15 min**, urgent after **1 h**, critical after **1 day** (keep limit nears). Defaults as shown; IT can change each.
- Through platform-core notifications (mail / Teams / Slack as configured). One message per outage step, and an "ended" message when it clears.

## Safety
- Every step idempotent: a retry never duplicates findings, files or deliveries (prove it with tests).
- 0112's guard (a case with nothing planned) re-queues it once by itself; if it happens again, it is kind C.
- Scorecard (0106) and Reports count Stopped cases; the target is about zero.

## Cases page (ties to 0108)
- Needs you holds only business work (review, approval, unreadable pages).
- Stopped (kind C) cases are IT's: IT works them in **Support** (it already lists them). They are **not on business users' Cases dashboard**; Reports shows the count "With IT: N"; Find still opens one, and its case panel says "With IT". No "Send to IT" button.

## Proof
Tests: stop the AI server mid-batch → cases wait, one alert, all resume and finish when it returns, none Stopped; a bad page with a healthy server → only that page to Review; a forced defect → Stopped with bundle; alert timings follow IT's settings. The 0106 round with the AI server stopped for 10 minutes finishes every case with no person.
